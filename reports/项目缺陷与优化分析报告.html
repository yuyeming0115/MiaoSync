执行摘要

项目已经具备 Go 单二进制、内置 Web GUI、mirror/backup、快照、冲突副本和危险删除确认等 MVP 能力。当前测试与构建均通过，但同步内核还缺少可靠的事务边界，因此不建议直接用于唯一数据副本。

最高优先级：先修复删除状态矩阵、失败后错误提交快照、非原子覆盖和并发执行，再扩展加密、自动触发或断点续传。

关键缺陷

P0删除动作与恢复复制可能同时生成

internal/sync/engine.go:94-141 先处理“独有文件补齐”，再处理快照删除检测。同一路径可能得到反向复制和删除两个动作，导致一次运行后两端仍不一致。

修复：为每个路径建立完整状态转换矩阵，每条路径只允许一个最终决策。

P0动作失败后仍提交快照

Run 在 Apply 有错误时仍调用 savePairSnapshot。截断文件、未删除文件或失败冲突会被写入成功基线，下一轮可能反向污染正确数据。

修复：引入 run journal，只有逐动作成功且全局复验通过才提交快照。

P0复制和冲突替换不是原子操作

os.Create(to) 会先截断目标；ConflictNewer 还会先删除旧文件。磁盘满、拔盘或进程退出都可能留下半文件或直接丢失旧版本。

修复：同目录临时文件、Sync、hash 校验、原子替换，失败时保留原目标。

P0Web 服务没有同步独占锁

Server 没有 mutex 或任务队列，多个请求可同时改文件、配置和 snapshot。当前 race 测试未覆盖这个场景。

修复：增加单任务 RunManager，第二个执行请求返回 409 Conflict。

P1backup 方向不使用 role

代码只按节点数组顺序决定 pair 的前后方向，source/target 字段没有参与规划。三节点结果会随选择顺序改变。

修复：backup 强制一个 source、多个 target；mirror 只允许 peer。

P1预览和执行存在 TOCTOU

预览、危险确认和执行各自重新扫描，用户确认的动作不一定是实际执行的动作。

修复：生成绑定快照版本与根路径指纹的 plan ID，状态变化后使计划失效。

P1路径安全校验不足

未拒绝相同目录、祖先/子目录、符号链接别名和高风险根目录。嵌套节点可能造成递归复制或容量爆炸。

修复：Abs/Clean/EvalSymlinks 后检查 canonical path 关系并二次确认。

P1大小写折叠会吞掉文件

所有平台统一将路径转小写作为 key；区分大小写磁盘上的 A.txt 与 a.txt 会被静默覆盖。

修复：扫描时检测 compare key collision，阻止执行并展示冲突。

P1冲突副本可能继续传播

代码生成 *.conflict-*，默认 ignore 没有该规则；三节点时副本可能变成新业务文件并进入快照。

修复：将副本集中放入 .miaosync/conflicts/<run-id>。

P1每个 pair 重复全量扫描和 hash

三节点的预览、执行、每 pair 快照保存都会重复读取文件，大文件场景吞吐退化明显。

修复：每轮每节点扫描一次，缓存 metadata/hash，最后一次提交快照。

P2快照缺少版本和恢复元数据

没有 schema version、卷/目录身份、同步组 ID、成功 run ID 和校验信息，移动硬盘复用或快照损坏时难以安全恢复。

P2配置、HTTP、测试与文档仍需工程化

启动加载不做严格枚举校验；HTTP 缺少 body 限制、超时、优雅关闭；关键失败路径无测试；注释中的 blake2b 与实际 SHA-256 不一致。

推荐同步状态机

固化输入

获取运行锁，加载并严格校验配置，生成 canonical path 和不可变 plan ID。

全局规划

每节点只扫描一次，检查路径、卷身份、大小写碰撞和符号链接，再生成全局计划。

原子执行

动作写入临时文件并校验；删除隔离；逐项记录 journal，支持取消与恢复。

一致性提交

全局复验通过后一次提交所有快照；失败则保留旧基线并输出可恢复报告。

分阶段路线

阶段主要工作退出标准
P0 止血删除矩阵、原子复制、失败不提交快照、同步锁、路径/链接/大小写校验。故障注入不丢旧文件；删除、失败恢复、并发测试通过。
P1 语义收敛role 驱动 backup、plan ID、冲突中心、版本化快照、三节点全局规划。节点顺序无关，重复执行幂等，计划变化需重新确认。
P1/P2 性能单次扫描、metadata 快速路径、hash 缓存、取消和结构化日志。每轮每节点最多一次全量扫描，未变化文件不重复读内容。
P2/P3 发布CI、跨平台产物校验、配置/快照迁移、诊断包和回滚说明。构建、升级、故障诊断流程可重复。

建议新增的最小测试集

TestMirrorDeletePropagatesOnce、TestApplyFailureDoesNotCommitSnapshot、TestAtomicCopyKeepsOldTargetOnFailure、TestBackupUsesRolesNotNodeOrder、TestThreeNodeMirrorIsOrderIndependent、TestRejectSameAndNestedRoots、TestRejectCaseCollision、TestSymlinkDoesNotEscapeRoot、TestConcurrentSyncReturnsConflict、TestPlanIdRejectedAfterFilesystemChange、TestCorruptSnapshotEntersRecoveryMode。

结论

项目骨架和产品方向是合理的，当前主要问题集中在同步事务边界，而不是 UI 或依赖。建议暂停新增大功能，先完成 P0 与关键 P1，使系统从“可演示 MVP”提升到“可用于真实数据的工具”。在修复完成前，建议仅对已有额外备份的数据使用，并始终先执行预览。
