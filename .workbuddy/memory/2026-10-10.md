## 架构咨询答疑 + UI 亲验迭代 + 冲突路径 bugfix（v0.1.0 后）
- 用户疑问「不顺手是否 Go 架构导致、是否换栈」：结论不换。①不顺手是功能层（托盘/插盘触发未做），非语言层；②iOS/安卓不需要跑 MiaoSync——硬盘=通用接口，系统文件管理器直接读写，移动端支持零成本获得；③换栈只在需求变为原生桌面集成/P2P 移动同步时才合理（且 iOS 后台同步物理受限）。用 show_widget 架构图说明「硬盘即协议」。
- 本轮打通 agent-browser 无头浏览器截图能力（npm 装 agent-browser + npmmirror 镜像下 Chromium 155，~200MB），首次亲眼验证 UI 渲染，终结盲改循环。经验：截图白屏先 `close --all` 重开会话（多标签竞态）；`eval` 可能落在 about:blank 上下文。
- UI 改动（已提交 main d936513）：全局字号 11.5-14px→13.5-15.5px（用户视力适配）、侧边栏加「三步上手」提示卡填留白、日志空态占位文案。经截图迭代验证。
- Bugfix（6a86d11）：handleConflict 用 TrimPrefix 绝对路径推导归档子目录，正斜杠配置路径（YAML 常见）下失配 → mkdir "...\conflicts\C:" 失败、冲突处理必失败。改为用 RelPath 推导。回归测试 TestConflictArchiveWithForwardSlashRoot。E2E 复测通过+幂等。
- 性能实测（1600×4KB 文件）：冷预览 0.49s、冷执行 0.59s、稳态预览 0.68s、二次计划 0 动作——文件数场景无瓶颈；性能风险只在大文件字节量（copyFile 双哈希重读源文件）→ 阶段 C 优化（mtime 快速路径 + 复用 plan 哈希）。
- 工程：.gitattributes 统一 LF（修 Windows autocrlf 导致 gofmt 全量报错）；教训：commit 前检查 status，误提交过 miaosync.exe~ 与截图（已 cce28e6 清理）。
