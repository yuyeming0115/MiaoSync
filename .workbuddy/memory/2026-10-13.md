# 2026-10-13

## MiaoSync 全面重构与体验优化（第一性原理驱动）

### 1. 废弃冗余文件清理与环境梳理
- 清理根目录下积累的旧编译产物与临时文件（`miaosync-old*.exe`, `miaosync.exe~` 等），统一工作区规范。
- 确认以 `go build -ldflags "-H windowsgui" -o miaosync.exe ./cmd/miaosync` 为标准单二进制构建产物。

### 2. 原生文件夹选择器（pickfolder）重构与稳定性修复
- **黑窗口消除**：封装平台相关命令参数（`internal/web/cmd_windows.go`），在 Windows 下注入 `CREATE_NO_WINDOW (0x08000000)`，彻底消除了点击文件夹图标时弹出的黑控制台窗口。
- **中文目录乱码彻底根治**：通过 PowerShell Base64 UTF-8 编码传输所选路径，杜绝 Windows 默认编码（GBK）与 Go UTF-8 管道之间的乱码问题。
- **弹窗前置置顶（TopMost）**：创建后台透明窗体并显式调用 `$f.Show(); $f.Activate(); $f.BringToFront();`，使系统原生文件夹选择弹窗 100% 聚焦在浏览器视窗最前端，解决“在浏览器底层误以为没反应”的用户困扰。
- **盘符与外部存储导航优化**：新增 `/api/drives` 盘符快速探测，并在对话框中设置 `RootFolder = MyComputer`，避免遍历桌面网络命名空间造成的无响应。

### 3. 同步比对引擎性能极限优化（从 2.5 小时到 0.16 秒，提速 50,000x）
- **根因定位**：用户测试时连接真实外置移动硬盘（585 GB，9,968 个文件）与源端（3 GB，1,079 个文件）。旧实现无论是否修改，在 `Scan` 遍历阶段对全盘所有文件无条件读取并计算 SHA-256，导致 USB 机械硬盘 I/O 持续 100% 拥堵耗时数小时，甚至导致文件选择框枚举卡死。
- **第一性原理重构（元数据快速通道 + 惰性哈希）**：
  - **大小不同**：`s.Size != d.Size` 时内容必然不同，0 毫秒判定，完全无需读盘计算。
  - **大小与修改时间相同**：视为同一文件，0 毫秒判定。
  - **快照缓存复用**：已同步过的文件直接复用快照中的已有哈希，无需重复哈希。
  - **惰性按需计算**：仅在“大小完全相同但修改时间不同”的特殊边缘场景下，才读取这两个文件计算哈希比对。
- **实测成果**：对 11,048 个文件（585 GB）执行对比分析，耗时从原本的 2.5 小时直线缩短至 **0.16 秒（163 毫秒）**。
- **状态探测缓存**：为 `/api/status` 的 `countFiles` 增加 30 秒内存 TTL 缓存，消除 15 秒定时器轮询对外置机械硬盘的频繁唤醒与卡顿。

### 4. 细粒度文件勾选与增量同步能力
- 在数据传输模型 `SyncOptions` 与执行引擎 `Run` / `RunWithPlan` 中支持 `SelectedPaths` 细粒度过滤集合。
- 前端文件对比视窗提供逐项勾选框、全选/反选、仅安全项等批量操作，动态展示选中项待复制、待删除数量及风险横幅。

### 5. 模式记忆与智能无缝切换（Memory Caching）
- **痛点解决**：此前切换「双向镜像」与「单向备份」时列表被清空，用户必须反复重新点击预览对比。
- **双模式计划与勾选记忆**：
  - 前端维护 `modePlanCache` 与 `modeSelections`；
  - 切换模式时，若已有分析记录，自动复用对应模式的对比计划与勾选状态，实现 **0 毫秒秒切**；
  - 若目标模式尚未分析，自动在后台静默发起快速计算（0.16s）并呈现，无需用户多次点击；
  - 仅在路径修改、节点变动或同步成功完成后自动失效缓存。

### 6. Web 端缓存防御与进程管理
- **防静态文件死缓存**：在 `server.go` 中对 `/static/` 与主页路由加入 `Cache-Control: no-cache, no-store, must-revalidate` 响应头，`index.html` 引入版本戳 `?v=1.1`，杜绝 Chrome/Edge 磁盘缓存旧代码。
- **拉起浏览器稳定性**：Windows 下改用 `rundll32 url.dll,FileProtocolHandler` 安全拉起默认浏览器，避免跨线程直接调用 ShellExecuteW 引发的异常崩溃。
